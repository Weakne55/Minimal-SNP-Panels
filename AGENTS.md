# AGENTS — правила разработки Minimal SNP Panels

## Научная задача и границы

Цель проекта — подготовить воспроизводимый вход multi-sample VCF/BCF, затем определить генетическую структуру и, по проверенным `population_labels.tsv`, отобрать минимальные SNP-панели для белух и белых медведей. **Текущий технический приоритет — FASTQ → VCF**, а два VCF-режима остаются заглушками, без вымышленных меток и SNP-панелей.

## Актуальная архитектура

- Единственная пользовательская точка входа — **`python pipeline.py`**, полноценный argparse/`--help`. Отдельный `cli.py` и `run_pipeline.sh` не используются.
- `src/minsnp/`: `core.py`, `resources.py`, `slurm_wgs.py`, `wgs.py`, `joint.py`, `analysis_stub.py`; прежние downstream-модули не запускаются основным интерфейсом.
- `stages/*.sh` содержат вызовы проверенных инструментов BWA-MEM3, samtools, mosdepth, GATK, bcftools. Не переписывать их без диагностированного дефекта.
- `config/pipeline.yaml`: общий лимит `max_parallel_samples`; ресурсы `sample` (один животный WGS job) и `joint` (один вид). Никаких отдельных бюджетов на Bash-стадию, глобальных CPU/RAM-ограничений либо SLURM array по хромосомам.
- Один **общий** WGS SLURM array для всех видов; после успешного завершения всего array отдельное joint-задание на каждый вид. Внутри каждой задачи хромосомы обрабатываются последовательно.
- Вид определяется столбцом `species` FASTQ TSV. Смешанные виды допустимы в общей отправке, но не в одном joint BCF.

## Метод изменений (по SKILL.md)

1. **First Make it Work:** сначала конкретный критерий результата и маленький воспроизводящий тест; проверить, что до исправления тест падает по ожидаемой причине.
2. **Then Make it Right:** устранить причину, не маскировать исключения и не дублировать решения в Python, Bash и YAML. Не вводить новые модули без необходимости.
3. **Follow Practice:** сохранить журнал изменений и причин, выполнить тесты, проверить ресурсы и `git diff --check`. Делать небольшие коммиты с описанием «почему/что/как проверено».
4. Комментарии, docstrings и пользовательские ошибки — **на русском**. Идентификаторы и технические имена параметров — на английском.
5. При отсутствии дополнительных анализаторов CRAP/Dryer/Mutator не имитировать их результаты; использовать доступные проверки и явно сообщить ограничение.

## Контракты и безопасность

- Перед запуском проверить TSV, уникальность пар sample/run/library, существование FASTQ, виды и доступность референса с индексами.
- Не считать run отдельным животным; объединять runs одного sample только в пределах одного вида.
- Отдельные sample manifests и результаты должны быть изолированы, чтобы параллельные workers не записывали один и тот же файл.
- План, входные TSV и версия кода фиксируются при подготовке запуска; любые изменения должны останавливать продолжение, а не приводить к смешению версий.
- `--submit` должен явно разрешать SLURM submission. Без него SLURM-вызов остаётся read-only dry-run. Запретить повторную отправку jobs одного run-id.
- `--resume` должен пропускать только проверенные результаты. Неполные BAM/gVCF не считать готовыми; сомнительные файлы сохранять под диагностическим именем. При неуспехе любой WGS-задачи joint по зависимости `afterok` не запускается.
- Для GATK joint проверять полный набор образец × аутосома и образцы окончательного BCF/VCF.
- Не удалять готовые BAM/gVCF, FASTQ и архивы результатов без отдельного решения пользователя. Не использовать реальные FASTQ в модульных тестах.
- Не модифицировать активный код, пока на нём работают SLURM-процессы. Если нужно — отдельная рабочая копия, новые run-id и outdir.

## Документация и репозиторий

- `README.md` — публичная инструкция. `docs/PROJECT_GUIDE.md` — единый технический документ. Изменять другие MD только по отдельному запросу.
- `data/` и `literature/` не изменять при рефакторинге интерфейса; FASTQ, BAM, gVCF, BCF не публиковать в Git.
- `legacy/` остаётся на сервере и не отслеживается в Git; `wgs_test/` — вспомогательные утилиты, не основной путь запуска.
- Структуру тестов поддерживать даже если каталог `tests/` локально исключён из Git.

## Критерии готовности текущего этапа

`python pipeline.py --help`; режим dry-run без `sbatch`; общий array с ограничением параллельных **животных**, joint отдельно по виду; однозначные CPU/RAM и time на sample/joint; безопасность `--resume`; тесты; реальный тест на нескольких животных с проверенными многосэмпловыми VCF/BCF. До этого не объявлять новую версию validated end-to-end.
