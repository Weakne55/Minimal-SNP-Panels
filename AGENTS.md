# Правила разработки — Minimal SNP Panels

## Цель и интерфейс

- **Основной pipeline:** индексированный multi-sample VCF/BCF одного вида + TSV `sample_id`, `population` (опционально `group`) → QC → информативность SNP → LD → классификация / leakage-aware CV → панели.
- **Вспомогательные WGS-этапы:** paired-end FASTQ → BAM → per-autosome gVCF → joint BCF/VCF. Определение `population_labels.tsv` по PCA/кластеризации — исследовательская ветка, не обязательная зависимость основного pipeline.
- Источники истины об исполняемом коде: `run_pipeline.sh`, `src/minsnp/`, `stages/`, `config/*.yaml`; документация: `README.md` и `docs/PROJECT_GUIDE.md`.

## Безопасность вычислений

1. Работа — в `develop`; **минимальные точечные изменения**, без переписывания проекта.
2. **Не запускать** повторно `wgs_test/wgs_pilot.py submit --confirm` или `tools/wgs_pilot.py submit --confirm` для `pilot_20261030`. Не отменять и не пересоздавать `943428`, `943430`, `943429`, `943431` без отдельной диагностики и разрешения пользователя.
3. В уже сгенерированных SLURM-скриптах закреплён абсолютный путь `tools/wgs_pilot.py`. На `sphinx` сохранять локальный `tools/` и соответствующие входные TSV до окончания текущих вычислений. Каталог `wgs_test/` — публикуемая копия вспомогательных инструментов.
4. Не изменять параметры стадии, конфигурацию, reference, входной manifest, output path и checkpoints посреди расчёта. Не удалять BAM/gVCF, индексы, GenomicsDB или FASTQ до проверки downstream-зависимостей.
5. `sacct` на `sphinx` может не работать: использовать `squeue`, `scontrol`, stdout/stderr, manifests и markers. Временные состояния не выдавать за завершённые результаты.

## Стиль и тестирование

- Bash содержит научные вызовы (`stages/`), Python — контракты, оркестрацию, статистику и визуализацию; предпочитать небольшие функции, ясные ошибки и валидируемые входы.
- Каждое исправление поведения сопровождается регрессионным тестом. До/после проверить `PYTHONPATH=src python -m pytest -q` (локальный `tests/`), `bash -n run_pipeline.sh stages/*.sh`, `python -m compileall -q src`.
- Тесты и изменения кода проверять **без** реального `sbatch`, реальных WGS или перезаписи production results. На сервере `tests/` может существовать локально, хотя не публикуется на GitHub.
- Не применять автоматически исторические скрипты генерации документации (`update_docs_inplace.py`, секция документов `configure_wgs_slurm.py`): они могут восстановить устаревшие файлы.

- Референсы: белуха `GCA_059928025.1` (21 аутосома), медведь `GCA_062004589.1` (36). Не смешивать виды/сборки.
